# 通信领域中文审稿（review_comm_cn）

## 任务概述

读取用户提供的 **PDF 论文**，基于论文实际内容撰写一段 **中文通信/信息类学术审稿意见**。输出为连贯 prose，而非表格或打分卡；不给出录用/拒稿结论，除非用户明确要求。

## 工作流程

### 1. 读取 PDF

1. 确认 PDF 路径（用户附件、工作区文件或指定路径）。
2. 使用 **pdf** skill 提取全文：优先 `pypdf` 或 `pdfplumber`；扫描件或提取质量差时尝试 OCR。
3. 通读并记录：
   - 标题、摘要、关键词
   - 引言中的问题陈述与应用场景
   - 方法/系统/算法设计与声称的贡献
   - 实验设置、对比方法、指标与图表
   - 结论与局限性
4. 信息不足时，基于已有内容保守推断，**不编造**引用、数值、对比结果或未出现的实验。

### 2. 分析论文

按以下维度扫描全文，为「优点」和「问题」收集 **可追溯到论文事实** 的论据：

| 维度 | 关注内容 |
|------|----------|
| 场景与动机 | 面向何种网络/系统/应用；问题是否界定清楚 |
| 创新点 | 相对现有工作的技术增量；是否明确写出 |
| 方法设计 | 模块划分、算法流程、假设与复杂度 |
| 实验 | 数据集、基线、指标、消融、统计显著性 |
| 表达与排版 | 定义、符号、定理证明、图表清晰度 |

撰写前阅读 `references/example_review.md` 把握语气、段落结构与问题粒度。

### 3. 撰写审稿意见

使用下列 **固定结构**（Markdown 输出）：

```markdown
# Review_[论文主题简短描述]

[开篇段落：2–4 句]
- 第一句：论文针对的应用/场景 + 提出的核心方案/方法；
- 随后：主要技术组合或创新机制（基于摘要与方法节事实）；
- 末句或穿插：1–2 条可核实的优点（如算法描述详实、实验覆盖某类指标等），语气客观、不夸大。

本文存在几点问题。

1、[问题 1：完整陈述，可含疑问或改进建议]

2、[问题 2]

…

N、[问题 N]（共 5–10 条）
```

**开篇段落**要求：
- 必须基于论文事实，概括 **场景** 与 **创新点**；
- 优点融入段落，**不要**单独开「优点」小标题或长列表；
- 避免空泛套话（如「具有重要意义」而无具体内容）。

**问题列表**要求：
- **5–10 条**，使用中文序号 `1、2、3、…`；
- 每条针对论文 **具体章节、Claim、图表或实验**，可操作、可验证；
- 语气建设性：可用「建议…」「需要补充…」「表述不够充分…」，避免攻击性措辞；
- 证据不确定时用「目前文中…」「建议作者进一步说明…」。

### 4. 问题来源（必须覆盖）

从下列 **六类** 中选取与论文最相关的类别生成问题；至少覆盖 **3 类**，且每条问题应能归入其中一类：

1. **表达不清晰** — 阶段目的不明、逻辑跳跃、符号/术语混用、定理或证明难读
2. **定义明显有问题** — 概念界定模糊、与领域惯例不符、符号前后不一致
3. **实际内容与声称的贡献存在冲突** — 摘要/引言承诺与正文或实验不一致；通用方法未体现场景特性
4. **实验设计不完整** — 缺基线、缺消融、数据集/场景单一、指标选取不当、未考虑实际约束
5. **结果分析不全面** — 缺曲线/可视化、缺误差分析、未讨论失败案例或复杂度/开销
6. **图表及排版混乱** — 缺流程图/算法图、图表信息不足、排版影响阅读

详细写作角度见 `references/weakness_categories.md`。优先写 **与本文内容强相关** 的问题，避免模板化重复。

### 5. 输出与保存

- 默认在对话中直接给出完整审稿意见。
- 用户要求保存时，写入工作区，文件名建议 `Review_<论文关键词>.md`。
- 不输出英文审稿，除非用户另行要求。

## 风格规则

- **语言**：简体中文，通信/信息类期刊审稿语气。
- **事实性**：每条意见应能在论文中找到依据或合理缺失点；不虚构他文对比或实验数据。
- **篇幅**：开篇 80–200 字；每条问题 1–3 句，总长适中、信息密度高。
- **与 paper-reviewer 的区别**：本 skill 采用 **单段总结 + 编号问题** 的通信审稿体例（见 example_review），而非「论文总结 / 论文优点 / 过渡句」三分结构。

## 质量自检（输出前）

- [ ] 开篇是否写明场景与创新点？
- [ ] 是否至少 1 条基于事实的优点？
- [ ] 问题是否 5–10 条、序号格式为 `N、`？
- [ ] 是否至少覆盖 3 类问题来源？
- [ ] 是否存在无依据的批评或编造数据？
- [ ] 整体语气是否与 `references/example_review.md` 一致？
